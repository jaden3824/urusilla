# Urusilla Red-Team and Benchmark Audit Response

Date: 2026-08-20  
Status: pre-alpha remediation record; unresolved items remain release blockers

## Purpose

Two parallel project-internal workstreams reviewed the prototype before publication: one adversarially tested semantics, provenance, the human Lens, A2A binding, canonicality, and resource limits; the other reproduced benchmark arithmetic and challenged comparison methodology. This document records the resulting changes without presenting the reviewers as external organizations, independent reproductions, or adopters.

## Semantic and protocol findings

| Finding | Current disposition | Evidence and remaining boundary |
|---|---|---|
| R1: shape checks were described as semantic or authority validation | Partially remediated | `urusilla.py` now rejects unknown top-level fields, enforces core node fields and types, binds acts to body kinds, binds `COMMIT.debtor` to the declared sender, and exposes a separate deployment-check API. A real schema registry, ontology validation, authenticated ledger, and policy engine remain unimplemented. |
| R2: the per-use provenance contract was inconsistent and absent from A2A messages | Partially remediated | One camelCase source-manifest schema, restricted canonicalizer, source-ID derivation, and negative vectors are published. The A2A Message now requires a 32-hex `source_id`. The release remains unsigned, has no production trust store, and cannot authorize effects. |
| R3: the human Lens hid security-relevant differences | Remediated for the reference view | The default view now includes the complete canonical JSON, message and translator hashes, and explicit schema/source/authentication statuses. Differential tests cover priority, metadata, and expiry. Localized fluent text is still a summary, never an approval surface. |
| R4: the A2A fragment omitted service-parameter activation and sender binding | Partially remediated | The adapter now emits `A2A-Version` and `A2A-Extensions`, validates activation membership and roles, pins Message/context/task identifiers, and binds the inner sender to a caller-supplied authenticated principal. Official-SDK, gRPC, and deployed-client conformance remain open. |
| R5: tuples and shadow fields violated the claimed round-trip domain | Remediated | Tuples and unknown top-level fields are rejected, nested values are canonicalized recursively, and accepted negative zero becomes canonical positive zero. Regression tests cover both failures. |
| R6: dictionary, Base64, and gzip paths allowed avoidable amplification | Remediated at the codec boundary | v0.1 duplicate detection is linear-time, A2A Base64 is size-preflighted, and v0.2 decompression is output-limited with bomb and trailing-member tests. A deployment must still cap its HTTP body and JSON parser before this library is called. |
| R7: expiry, replay, lifecycle, and causal ownership lacked an executable ledger | Open | The structural codec requires causal IDs for effectful acts, but it does not prove the target exists or that a transition is fresh and authorized. No effectful pilot is permitted. |
| R8: the original “blind” teachability pilot was open-label | Claim remediated; production gate open | The result is now titled an open-label smoke pilot. A neutral-ID follow-up publishes its four structural failures and leaves the standardized Teachability Score null. Multiple model families, precommitted scoring, exact graphs, and unseen live partners remain required. |
| R9: v0.2 profile installation lacked signed authorization and used mutable registry state | Open | The dictionary fingerprint remains a lookup identifier, not trust. v0.2 is benchmark-only until signed profile authorization, immutable session pins, downgrade handling, and revocation exist. |
| R10: the warm profile was in-sample and lacked strong baselines | Partially remediated | Deterministic CBOR, MessagePack, typed Protobuf, and complete representative A2A JSON requests are now measured. Grouped holdout and two sealed official-example corpora are published, but the specialized surfaces do not demonstrate external compact wins; representative independently operated traffic remains mandatory. |
| R11: identifier and diagnostic-wrapper rules diverged | Partially remediated | One wrapper now requires an immutable commit URL, 32-hex source ID, full Capsule digest, and privacy-scrubbed Base64url payload. Unicode confusable policy and recipient-order semantics remain open. |
| R12: receiver-specific vocabulary tokens could be mistaken for safe model input | Remediated at the experimental profile boundary | v0.7 declares raw `R7` text decoder-before-model only, binds exact tokenizer fingerprints and token IDs, rejects normalization, and requires canonical decoding before model exposure. A finite word denylist is not treated as prompt-injection protection. |
| R13: fallback wrapping imposed token overhead after every compact candidate lost | Remediated for two explicitly separated contracts | v0.8 bound fallback leaves raw plain receiver text unchanged when authenticated transport metadata is already out of band. Compact modes win 0/172 bound and 0/172 standalone comparisons on the development corpus; standalone text is 5.85% to 6.80% larger. On the retained corpus, both contracts record 0/168 compact wins and standalone cold overhead is 2.24% to 3.00%. No external-corpus compression claim is made. |
| R14: repeated full snapshots ignored state correlation | Experimental mitigation only | v0.9 checkpoints full state and uses authenticated deltas only on strict complete-record wins. It rejects replay, reordering, loss-contaminated state, and base-digest mismatch, but the evidence is synthetic and excludes model use, concurrent branches, transport retransmission, and production key establishment. |
| R15: cross-runtime work could be mislabeled independent | Claim boundary remediated | The separately written Node.js lane is labeled same-project compatibility against Python-oracle-derived fixtures. It is not an external reproduction, adopter, security certification, or full-conformance result. |
| R16: aggregate semantic trees had no shared node budget across body and metadata | Remediated in the reference source; release verification pending | The Python semantic and v0.2 decoders now share a 250,000-value aggregate budget across body and metadata, with exact-limit and plus-one boundary tests. The release claim remains bound to the current CI result and immutable source revision. |
| R17: narrow serialization gains were being used as a proxy for general conversation | Claim boundary remediated; performance gap open | The frozen 2,542-turn four-family lane passes H1 exact no-regret but fails H2 general compact value and H3 repeated-context value; H4 is not evaluated. Warm carrier saving is 0.65% to 0.80%, all cold plans retain raw, post-decode API-input saving is 0%, and the external-profile control adds 165.60% to 183.98% tokens. General unfamiliar-agent saving remains 0%. |
| R18: tokenizer cache and zlib drift could silently change broad-lane results | Reproducibility boundary remediated | cl100k and o200k now load only explicit local hash-pinned `.tiktoken` assets, all four tokenizer assets are verified before use, and the measurement fails unless zlib compile and runtime versions both equal 1.2.12. The evaluator performs no acquisition or network fallback. This postmeasurement hardening changed no candidate, gate, or non-latency outcome; the original chronology is project-internal, not external preregistration. |
| R19: exact payload delivery could be mistaken for causal receiver comprehension | Claim boundary remediated; live evidence open | The sender-output, model-visible request, and receiver-event digests prove which bytes were delivered, not that the receiver used them. Current synthetic adapters can emit a fixed output without reading the action-state. A separate offline `/2` validator now enforces precommitted one-pointer A/B probes, missing/shuffled abstention controls, replay rejection, per-stratum coverage, inclusive accounting, and preservation of adverse outcomes, while frozen v1 artifacts remain unchanged. Its current missing arm is not a measured no-payload accuracy baseline, and it does not yet implement semantic-invariance, composition-holdout, declared field-universe, powered worst-stratum, or calibration-versus-headline seed controls identified in public external review. It makes no provider call and cannot establish chronology, blinding, independence, authenticity, or causal use; no comprehension or route-level language claim is permitted until a newly frozen study closes those gaps. |

## Benchmark findings

| Finding | Disposition |
|---|---|
| MF-1: corruption tables omitted accepted-but-unchanged cases | Both v0.1 and v0.2 reports now publish rejected, changed, and unchanged counts. |
| MF-2: “canonical JSON” overstated sorted CPython JSON | Reports now call it a sorted, minified, same-runtime study profile and do not claim RFC 8785. |
| MF-3: latency rows performed unequal work | Reports explicitly describe implementation-path timings. The strong-codec study invokes the shared validator for every codec and still discloses the extra v0.2 checksum/re-encode work. |
| MF-4: payload rankings were not A2A rankings | A reproducible full-request benchmark now includes Base64, Message fields, extension metadata, service headers, content length, and independent body gzip. It preserves the unfavorable result that gzip v0.1 RawPart requests are larger than gzip structured DataPart requests. |
| MF-5: v0.2 specialization was in-sample | The qualification is placed next to headline results. No general compression or task-efficiency claim is made. |
| Strict break-even formula used `ceil` on exact ties | The reports now use `floor(C/(B-W)) + 1` for the first strict byte win. |
| General dialogue had no broad raw-text control | A frozen four-family lane now uses bare UTF-8 as the mandatory fallback, an integrity-matched raw envelope as a control, generic DEFLATE/Brotli/Zstandard candidates under the same envelope, and causal history compression. H2 and H3 fail, so incremental universal-lossless tuning is stopped. |
| Compact state could be mislabeled lossless | A separate 399-prompt SGD gold-state oracle is labeled task-level and lossy. Its 7.48% to 23.34% prompt-token opportunity has no model call or accuracy result and cannot enter a codec or deployment claim. |

## Release verdict

The publishable artifact is an **experimental, unsigned semantic-schema and transport research snapshot**. It demonstrates deterministic structural transport, strong in-domain compression under one warm profile, exact transparent fallback, a reproducible failed broad-dialogue compact-value test, synthetic repeated-state delta behavior, same-project cross-runtime compatibility, explicit provenance plumbing, and reproducible failures. v0.7 saves 23,997 development and 4,302 grouped-holdout tokens but saves 0 OOD and activates in 0/12 cold plans; v0.9 saves 53.71% to 55.15% only on deliberately correlated synthetic state. The historical receiver gate reaches 27/28 but fails, and one historical pre-cutover internally operated sender pilot recorded 6/10 passes; that participant has not been rerun on current artifacts. The artifact does not demonstrate native model comprehension, representative deployed generalization, a complete semantic ledger, effect authorization, end-to-end task improvement, external independent reproduction, an external adopter, a standard, or state-of-the-art performance.

Until R7, R9, held-out cross-model evaluation, signature verification, and deployed A2A interoperability are complete, the only permitted modes are local read-only conformance work and non-effectful bridge experiments.
